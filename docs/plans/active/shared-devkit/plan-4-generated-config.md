# Plan 4 — `devkit sync`: generated config files and a drift gate

**Depends on:** Plan 2 (`devkit sync` is a package console script).
**Read first:** `docs/plans/active/shared-devkit/README.md`.

## Goal

Some config files have **no remote-reference mechanism** — GitHub reads only a literal
`.github/dependabot.yml`, ruff and mypy have no remote `extend`, VS Code has no
`tasks.json` inheritance. Those must be physical files in every repo. This plan renders
them from shared templates and adds a CI job that fails on drift, so "shared" survives
contact with reality instead of silently rotting.

**This pattern already exists in Carameli.** The PR Gate `mirror-sync` job verifies
`scripts/sync-agents-context.py` output is in sync, catching a bypassed or uninstalled
pre-commit hook. Plan 4 is that exact shape, one level up. Read `mirror-sync` in
`.github/workflows/pr-gate.yml` and the generator's docstring before designing this.

## What gets generated vs. referenced

| File | Why generated | Shared portion |
| --- | --- | --- |
| `.github/dependabot.yml` | GitHub reads only the literal path | ecosystems, grouping strategy, cooldowns, the `python` major/minor ignore rule |
| `ruff.toml` | no remote `extend` | the whole rule selection + the "bug-preventing, never superficial" policy |
| `mypy.ini` | no remote config | strictness settings |
| `.vscode/tasks.json` | no inheritance | the ~half that are generic (lint, test, deps, docker, pre-commit) |
| `.markdownlint.json`, `.yamllint.yaml`, `.gitattributes`, `.editorconfig` | same | all of it |
| `.pre-commit-config.yaml` | **partly** — `repo:`/`rev:` *is* natively remote | only `fail_fast` and file filters are local |

Note the last row: pre-commit hooks are the one category with a native sharing mechanism.
Carameli's two local hooks (`sync-agents`, `detect-secrets`) become entries in devkit's
`.pre-commit-hooks.yaml`, referenced by `rev: v1.x`. Don't generate what pre-commit can
already fetch.

## Step 1 — Template mechanism

Templates live in `src/devkit/templates/`. Each rendered file carries a header:

```yaml
# GENERATED by `devkit sync` from devkit vX.Y.Z — do not edit.
# Project-specific additions go in <file>.local.<ext>, which is merged in.
```

Two-part design so projects can extend without forking:

- **Base** — the template, identical everywhere
- **Overlay** — a project-local file merged over the base

The overlay is not optional polish. Carameli's `dependabot.yml` has genuinely
project-specific content that must survive: the `lint-typecheck-toolchain`,
`stylelint-toolchain`, and `test-env` groups exist because of specific compatibility
incidents, and the frontend `cooldown: semver-major-days: 30` is a deliberate choice.
A base that flattens those makes the file worse.

Merge semantics differ by format (YAML dict-merge for dependabot, TOML for ruff, JSON
array-append for tasks.json). Keep the merge rules dumb and explicit — a clever merger
that silently drops a key is worse than no sharing.

## Step 2 — The lint policy is prose, not config

`ruff.toml` and `mypy.ini` encode *what* is checked. The rule that matters —
**"always bug-preventing, never superficial"** — is a judgment call that a rule file
teaches and a config file cannot. Write it as `rules/lint-policy.md` in the Plan-1 plugin,
covering:

- Which rule families are on and why (correctness/security in, style/formatting out)
- The standing instruction never to silence a finding with `# noqa` / `type: ignore`
  without a comment naming the reason
- The escalation path when a linter is wrong (fix the producer, or report to the user with
  concrete options — never skip, never call an error "cosmetic")

The last point matches existing standing feedback (`feedback-never-skip-never-cosmetic`
memory) and belongs in the shared rule so every project inherits it.

## Step 3 — `devkit sync` and `devkit sync --check`

- `devkit sync` renders every managed file from base + overlay.
- `devkit sync --check` exits non-zero with a diff if any managed file differs.

Wire both:

- **Local:** a pre-commit hook (from devkit's own `.pre-commit-hooks.yaml`) runs `sync` on
  changes to overlay files. Follow the existing `sync-agents` precedent — generation stays
  local, the patched git hook auto-stages and retries.
- **CI:** a `devkit-sync` job in the reusable PR gate (Plan 3) runs `--check`. CI must
  **verify, never commit** — committing derived files back needs write access and hides
  the diff from review. That reasoning is already written down in
  `.pre-commit-config.yaml`; keep it.

## Step 4 — Migrate Carameli

For each managed file: diff the current content against the proposed base, move genuinely
project-specific parts to the overlay, and confirm `devkit sync` reproduces the file
byte-for-byte before deleting anything. A generated `dependabot.yml` that loses the
`python` semver-major/minor ignore rule would re-break the container lock — that ignore
exists because PR #43 auto-merged a 3.12→3.14 bump.

## Tests

- Round-trip test per managed file: base + Carameli's overlay renders exactly today's file.
  Write these **before** switching the files over; they are the safety net.
- `--check` returns non-zero on a hand-edited managed file.
- A test asserting every managed file carries the GENERATED header.
- Carameli-side: keep `test_check_lock_markers.py` and the dependabot invariant tests
  passing against the generated file.

## Definition of done

- [ ] `devkit sync` and `devkit sync --check` implemented, tested
- [ ] Round-trip tests prove byte-identical output for every Carameli managed file
- [ ] Overlay mechanism preserves the three dependabot groups and the `python` ignore rule
- [ ] `lint-policy.md` rule shipped in the plugin
- [ ] Local pre-commit hook + CI `--check` job both wired; CI never commits
- [ ] Carameli's managed files carry the GENERATED header and are reproducible
